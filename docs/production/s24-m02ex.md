# SECTION 24 — LES EXERCICES DU MODULE 2 (m02-e01 → e30, JSON complets)

## 24.0 Conventions du lot

Mêmes défauts que §18.0 (version 2, 4/4, rubrics standards). Ce lot introduit **deux extensions de spec** actées en §21 et formalisées ici :

1. **`spec.variants[]`** — l'exercice propose 2+ variantes de contraintes, l'élève en choisit UNE avant de composer (l'UI affiche le choix ; la soumission porte `variantId`). Nécessaire pour « décide laquelle avant d'écrire » (e20) ;
2. **`spec.submissionParts[]`** — exercice multi-soumissions séquentielles (e30 : Elena, puis ton brief). Chaque part a ses contraintes ; la part 2 peut porter `userBrief: true` (l'élève saisit son brief, stocké dans le payload, affiché dans le rapport).

Les nouvelles clés de contraintes sont récapitulées en §24.7 avec leur mécanique de vérification (toutes bâties sur `findMotifs`, `contour`, `tensionCurve`, `leapProfile` — déjà implémentés §10).

## 24.7 Nouvelles clés de contraintes (19) — mécanique de vérification

| Clé | Vérification (sur l'existant) |
|---|---|
| `minMotifCoverage` | % de notes couvertes par les occurrences du `bestMotif` (locations de `findMotifs`) |
| `cellArchetypes` | par segment : call = saut ≥5↑ + durée longue ; step = conjoint ≥80 % ; sigh = 2–3 notes desc., fort→faible ; signal = ≤2 hauteurs + entropie rythmique >0 |
| `mustContainInterval` / `intervalDirection` | `leapProfile` : présence de l'intervalle (en dt) dans la direction donnée |
| `givenCellAsMotif` | le `bestMotif` doit matcher la forme du `given` (intervalles+rythme, tolérance transposition) |
| `requireSequence` / `sequenceMaxRun` | occurrences transposées consécutives du même pas : ≥2 = séquence ; run > max = échec |
| `phraseStructure: "sentence"` | par segment : occ. 1 (mes. 1), occ. 2 exacte/transposée (mes. 2), densification (mes. 3), geste cadentiel (mes. 4) — via findMotifs + rhythmProfile |
| `minTransformations` / `allowedTransformations` / `requiredVariationTypes` | types de variation dans `MotifReport` ; inversion = intervalShape négatée (extension mineure de findMotifs, ~10 lignes) ; fragmentation = sous-motif (long. ≥2) à occurrences ≥3 hors occurrences complètes |
| `requireFragmentation` | cas particulier ci-dessus, fenêtré après la 1re exposition |
| `ascendingPhrasePeaks` | max(pitch) par segment strictement croissant (crédit partiel par paire ordonnée) |
| `phraseBarPlan` | frontières de phrases (`phraseAnalysis`) aux barres cumulées du plan (tolérance ±1 temps) |
| `minElisions` / `maxElisions` | frontière de phrase sans silence + réattaque temps fort (détection §21.3 déjà spécifiée) |
| `patternThenDeviation` | trajectoire des occurrences : [exact, exact, varié, exact\|même-variation] |
| `harmonizationVariants` / `structuralNotesCovered` | segments comparés : ≥50 % d'accords ≠ (racine ou qualité) ; chaque note structurelle (temps fort/longue) ∈ accord courant ou étrangère qualifiée |
| `guideToneTargets` | % des temps forts où la note ∈ {3,7} (ou {3,7,9,13} si profil jazz) de l'accord courant — seuil 0.6, crédit graduel |
| `prosodyPlan` | par segment : declamatory = longues sur appuis (corrélation durée×poids métrique >0) + anacrouses ; voluble = densité haute + longues rares — métriques de `rhythmProfile` |
| `requireAnacrusis` / `anacrusisPolicy` | 1–3 notes avant le temps fort à chaque occurrence du motif ; constant = même longueur d'anacrouse partout |
| `contourShape` / `flatTension` / `ambitusMax` / `maxDistinctPitches` / `minAvgDuration` | `contour()` matché aux 5 silhouettes ; écart-type de `tensionCurve` < seuil ; ambitus ; card. des pitch-classes... non — des hauteurs MIDI distinctes ; durée moyenne |
| `requireAmbiguousKey` | `estimateKey().ambiguous === true` (les contraintes de degrés basculent sur le meilleur candidat) |
| `minPerfectIntervalRatio` / `minRestRatio` / `maxPhraseNotes` / `climaxMinDuration` / `climaxApproachLeap` / `requireChromaticDrift` | ratios sur `leapProfile` (dt ∈ {5,7,12}) ; silence/durée totale ; notes consécutives sans silence ≥ 1 temps ; durée de la note-climax ; intervalle d'approche du climax ; suivi d'une hauteur du motif à travers les occurrences (+1 dt / N mesures) |

Plus les deux extensions de spec (`variants`, `submissionParts`) — schéma Zod : deux champs optionnels, mutuellement exclusifs avec les contraintes racine, validés au seed. **Aucune clé n'exige d'analyse nouvelle** hors l'extension inversion/fragmentation de `findMotifs` (~25 lignes) — la promesse §18.8 tient pour ce lot aussi.
