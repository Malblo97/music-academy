# SECTION 31 — MODULE 10, LEÇONS 4–6 (INTÉGRALES)

## 31.1 LEÇON m10-l04 — « Key Editor II : la vie des notes »

```mdx
---
id: m10-l04-key-editor-2
module: module-10-cubase
title: "Key Editor II : la vie des notes — velocity, CC1, CC11"
estMinutes: 25
skills: { daw_workflow: 0.6, orchestration: 0.4 }
---
```

### Pourquoi cette leçon est la plus rentable du module

La leçon 10 du Module 1 t'a donné la théorie : *velocity = l'attaque, CC = la vie de la tenue, une tenue sans courbe est une tenue morte*. Cette leçon te donne les gestes. C'est le savoir-faire au meilleur rapport effort/résultat de toute la maquette : **la différence entre « MIDI de démo » et « maquette qui émeut » tient à 80 % dans les contrôleurs continus** — pas dans les banques, pas dans le mix.

### 1. La lane de contrôleur : ton deuxième piano roll

Sous les notes du Key Editor vit la **controller lane** : clic sur le sélecteur (en bas à gauche) → Velocity, CC1, CC11, ou tout autre. Ajoutes-en plusieurs (le petit +) : ta vue de travail standard est **notes + CC1 + CC11 empilés** — trois étages, une seule vérité.

Le partage des rôles, une fois pour toutes :

| Contrôleur | Rôle | Métaphore |
|---|---|---|
| **Velocity** | la force de l'ATTAQUE — fixée à la frappe, une valeur par note | le geste du bras |
| **CC1 (modulation)** | l'INTENSITÉ du son pendant la tenue — dans les banques orchestrales : le crossfade entre couches de dynamique (le p, le mf, le ff *enregistrés*) | le souffle / l'archet |
| **CC11 (expression)** | le VOLUME expressif fin, par-dessus CC1 | la distance au micro |

**La règle des banques orchestrales** (l'immense majorité des libraries modernes) : les instruments à tenue (cordes, vents, cuivres) écoutent **CC1 pour la dynamique** — la velocity n'y contrôle souvent que l'attaque, voire rien. Corollaire : *le crescendo d'un cor s'écrit en CC1, jamais en velocity*. C'est LE malentendu qui produit des maquettes plates ; il meurt ici. (Les instruments à décroissance — piano, harpe, percussions — restent au royaume de la velocity : l10 M5, la fiche piano, te l'a préparé.)

### 2. Le geste : enregistrer les CC en jouant (pas les dessiner d'abord)

Deux écoles ; l'ordre professionnel est le suivant :

```
1. JOUE la ligne (les notes), sans te soucier des CC
2. REJOUE-LA en n'enregistrant QUE le CC1 : molette de modulation sous
   les doigts, la piste en overdub MIDI (Preferences → Record → MIDI :
   mode Merge), les yeux fermés, en CHANTANT intérieurement la phrase
   — tu "diriges" ta propre ligne
3. AFFINE au crayon dans la lane : les pointes trop hautes, les creux
   trop vides — l'édition corrige, elle ne crée pas
```

Pourquoi cet ordre : une courbe *jouée* a la respiration d'un geste ; une courbe *dessinée* a la régularité d'une rampe — et l'oreille entend la différence immédiatement. Le crayon et l'outil Ligne (rampes, sinus) servent pour les cas mécaniques : risers, pulsations de synthé (Module 6 en vivra), fades chirurgicaux.

### 3. Les cinq formes de CC1 à connaître par cœur

Toute l'expressivité orchestrale tient dans cinq gestes de molette — apprends-les comme un vocabulaire :

```
1. L'ARCHE DE NOTE      chaque tenue gonfle puis retombe légèrement
   ╱‾╲  (± 15 valeurs)  → le vibrato de vie de base : AUCUNE tenue plate
2. L'ARCHE DE PHRASE    le CC suit la tensionCurve de ta mélodie (l14 M1 !)
   la molette monte vers le climax, retombe à la résolution
3. LE CRESCENDO CIBLÉ   la rampe longue vers un point précis (l10 M1 §2 :
   "un crescendo a une cible") — souvent dessiné, lui, à l'outil Ligne
4. LE SFORZANDO-CREUX   pic bref à l'attaque, creux immédiat, regonflement
   ⌃╲╱‾  → le sforzando-piano-crescendo des grandes tenues dramatiques
5. LE NIENTE            partir de ~0 ou y mourir — l'entrée invisible
   (la clarinette de m05-l08 le fait acoustiquement ; le CC1 le fait
   pour tout le monde)
```

L'arche de phrase (n° 2) est la connexion profonde du produit : **ta courbe de CC1 devrait ressembler à ta courbe de tension** — le moteur qui analyse l'une (§10.2) décrit l'autre. Un jour prochain, le rapport de mission comparera les deux ; en attendant, c'est ton critère d'auto-contrôle.

### 4. Velocity : le travail qui reste

Même au royaume du CC, la velocity garde deux métiers : **différencier les attaques** dans une même phrase (l'appui du temps fort vs la note de passage — une ligne à velocity constante 100 sonne martelée même avec un beau CC1) et **piloter les articulations courtes** (staccati, pizz : pas de tenue, donc pas de CC — tout est dans la frappe). Geste de masse utile : sélection de notes → la lane Velocity → outil Ligne en pente douce = le decrescendo d'attaques en deux secondes.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Crescendo de cordes en velocity | rien ne bouge (la banque n'écoute pas) | CC1 — le réflexe à recâbler définitivement |
| Tenues à CC constant | le "MIDI de démo" : propre et mort | l'arche de note, partout, toujours |
| Courbes dessinées à la souris d'abord | des rampes d'ascenseur, pas des phrases | jouer la molette, corriger au crayon |
| CC1 ET CC11 utilisés pour la même chose | courbes qui se battent, volume incontrôlable | CC1 = dynamique de jeu ; CC11 = ajustement fin par-dessus (± 20 max) |
| Velocity constante « puisque le CC gère » | attaques martelées | la hiérarchie métrique (l08 M1) dans les frappes |

### La mission (m10-e04, PROUVÉE — la première à vérifier les CC)

Reprends ta soumission de s21 (le thème du héros) dans Cubase, piste cor du template : pose les notes, puis **enregistre le CC1 à la molette en deux passes** (arches de note + l'arche de phrase vers le climax F5). Exporte le MIDI *avec contrôleurs* et soumets. Le moteur vérifie : présence de CC1 sur ≥ 90 % des tenues > 1 temps, variance minimale par tenue (mort aux plateaux), et **corrélation CC1 ↔ tensionCurve ≥ 0.5** sur la phrase — l'arche jouée contre l'arche calculée. *(Extension `proofSubmission` : les contraintes `ccCoverage`, `ccPerNoteVariance`, `ccTensionCorrelation` — trois checkers nouveaux, mécanique triviale sur les events CC du MIDI importé.)*

- [ ] CC1 = la dynamique des tenues ; velocity = l'attaque (et les courtes)
- [ ] Jouer la molette, corriger au crayon — jamais l'inverse
- [ ] Les cinq formes : arche de note, arche de phrase, crescendo ciblé, sfz-creux, niente
- [ ] Ma courbe de CC1 ressemble à ma courbe de tension — c'est le critère

## 31.2 LEÇON m10-l05 — « Expression Maps : les articulations sous les doigts »

```mdx
---
id: m10-l05-expression-maps
module: module-10-cubase
title: "Expression Maps : les articulations sous les doigts"
estMinutes: 30
skills: { daw_workflow: 0.7, orchestration: 0.3 }
---
```

### Pourquoi cette leçon est la plus différenciante du module

Le problème qu'elle résout : ta banque de cordes a douze articulations (legato, staccato, pizz, tremolo, sordino… — le vocabulaire de l10 M1 §3 et des fiches M5), et chacune vit sur un patch. Sans système, tu crées douze pistes par section — le template-cathédrale — ou tu changes de patch à la main. L'**Expression Map** est la solution de Cubase : *une piste, toutes les articulations, commutées par la partition elle-même*. C'est LE savoir-faire qui sépare la maquette artisanale du travail de studio — et curieusement le plus mal documenté. D'où trente minutes ici.

### 1. Le principe en une image

```
SANS Expression Map :               AVEC :
12 pistes "Violins legato",         1 piste "Violins"
"Violins stacc", "Violins pizz"…    + une carte qui dit :
→ la mélodie éclatée en confettis     "quand la note porte l'articulation
  sur 12 pistes, illisible,            'pizz', envoie le keyswitch C0
  inexportable proprement              à la banque AVANT la note"
                                    → la ligne musicale reste UNE ligne ;
                                      l'articulation est un ATTRIBUT de
                                      la note, comme sa velocity
```

Le concept clé : l'articulation cesse d'être une affaire de routing pour devenir une **propriété musicale de la note** — exactement ce qu'elle est sur une partition. C'est aussi ce que le format d'échange du produit attend (le champ articulation des exports V1) : Expression Maps et produit parlent la même langue.

### 2. Anatomie d'une map (construire la tienne, pas à pas)

Ouvre **Expression Map Setup** (depuis l'Inspector de la piste). Une map = une liste de **Sound Slots**, chacun reliant trois choses :

| Colonne | Contenu | Exemple (cordes) |
|---|---|---|
| **Slot / nom** | l'articulation telle que TU la nommes | Legato, Staccato, Pizz, Trem, Sordino |
| **Art. (symbole)** | le symbole musical associé (pour le Score Editor) | ⌐, ·, pizz., ≋ |
| **Output mapping** | CE QU'ON ENVOIE à la banque pour l'activer | keyswitch C0 / D0 / E0… ou un CC (selon la banque : sa doc le dit) |

Deux **types de slot**, distinction cruciale :

- **Direction** : l'articulation reste active jusqu'au prochain changement (legato, sordino — les *états*) ;
- **Attribute** : l'articulation ne vaut que pour LES notes qui la portent (staccato, accent — les *événements*). 

Le mapping type/musique : les états de la fiche M5 (sordino = une couleur qu'on installe, l02) sont des Directions ; les gestes ponctuels sont des Attributes. Se tromper de type = des pizz qui « collent » sur toute la suite — le bug classique du débutant en maps.

### 3. L'utiliser : la lane d'articulations

Dans le Key Editor, la controller lane gagne une entrée **Articulations** : tu y poses les changements comme tu poses des notes — et le Score Editor affichera les symboles. Le workflow complet d'une phrase :

```
1. Joue la ligne entière en legato (la pensée musicale d'abord — l10 M1)
2. Dans la lane Articulations : pose les slots là où la phrase change
   (les staccati de la mesure 3, le pizz de la ponctuation finale)
3. Rejoue : la banque commute toute seule, la ligne reste UNE ligne
4. Les keyswitches n'apparaissent PAS comme des notes parasites dans
   ta partition — c'est tout l'intérêt vs les keyswitches "joués à la main"
```

Ce dernier point mérite son paragraphe : tu peux déclencher les articulations en jouant les notes-switch au clavier (C0, D0…) — rapide en jam, mais ces notes **polluent le MIDI** (elles sortiraient dans tes exports vers le produit, et l'analyseur les verrait comme des notes graves aberrantes — `orch.range-violation` garanti). L'Expression Map les garde hors de la musique. **Règle du produit : tout export MIDI de mission passe par des maps, jamais par des keyswitches joués.**

### 4. La stratégie : quelles articulations dans ta map ?

La tentation : mapper les 25 articulations de la banque. La sagesse (même logique que le template, l02) :

| Famille | Le kit de survie (5–6 slots) | Ce qui attend d'avoir servi trois fois |
|---|---|---|
| Cordes | Legato, Sustain, Staccato/Spiccato, Pizz, Tremolo, Sordino | harmoniques, col legno, sul pont… |
| Cuivres | Legato, Sustain, Staccato, Marcato, (Sourdine pour trompette — l09 M5) | rips, flutter… |
| Bois | Legato, Sustain, Staccato | trilles (souvent mieux en vraies notes), flatter… |

Une map par instrument du template Medium (l02 §1 : la promotion Sketch→Medium, c'est précisément *ajouter les maps*). Nomme les slots **pareil dans toutes tes maps** (Legato partout, pas « Leg » ici et « Sustain+ » là) : la cohérence fait la vitesse.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Keyswitches joués comme des notes | des C0 fantômes partout, exports pollués | la map, la lane, rien d'autre |
| Direction/Attribute confondus | le pizz qui colle, le legato qui saute | états = Direction ; gestes = Attribute |
| 25 slots au jour 1 | la map illisible, jamais utilisée | le kit de survie ; le reste sur preuve |
| Noms incohérents entre maps | tu cherches, tu sors du flux (le mal de l02) | mêmes noms partout, même ordre |
| Le switch posé SUR la note au lieu d'avant | la première note en mauvaise articulation (latence de commutation) | le slot se pose une double-croche avant l'attaque quand la banque est lente |

### La mission (m10-e05, GUIDÉE puis PROUVÉE)

Construis la map « Cordes — kit de survie » (6 slots, checklist guidée avec `verifyHint` par slot : « joue une note, entends-tu le pizz ? »). Puis programme la phrase fournie (8 mesures, PDF-mission : une ligne qui alterne legato / staccato / pizz / tremolo — chaque articulation notée) et exporte. **Vérification prouvée** : le MIDI importé ne doit contenir AUCUNE note sous G2 (le test anti-keyswitch — brutal et efficace) et les durées doivent refléter les articulations (staccati ≤ 50 % du temps, legato en chevauchements : `quantizeInfo` + profils de durée, checkers existants).

- [ ] Une piste, toutes les articulations : l'articulation est une propriété de la note
- [ ] Direction = état ; Attribute = geste — le bug classique meurt ici
- [ ] Le kit de survie d'abord ; noms cohérents entre toutes les maps
- [ ] Jamais de keyswitch joué : mes exports vers le produit restent purs

## 31.3 LEÇON m10-l06 — « Instruments et MediaBay : la bibliothèque domestiquée »

```mdx
---
id: m10-l06-mediabay
module: module-10-cubase
title: "Instruments et MediaBay : la bibliothèque domestiquée"
estMinutes: 20
skills: { daw_workflow: 1.0 }
---
```

### Pourquoi une leçon sur « chercher un son »

Parce que c'est le deuxième plus grand tueur de flux après le template absent : la demi-heure perdue à écouter quarante pads pour en garder un. Le compositeur qui livre a une bibliothèque **domestiquée** — indexée, taguée, présélectionnée. Cette leçon couvre les deux outils : l'instrument VST (le contenant) et le MediaBay (le catalogue).

### 1. Pistes Instrument vs Rack : la décision par défaut

Cubase offre deux façons d'héberger un VSTi : la **piste Instrument** (l'instrument ET sa piste MIDI fusionnés — simple, autonome, duplicable) et le **Rack** (l'instrument séparé, plusieurs pistes MIDI pointent vers lui — l'architecture des templates lourds multi-timbraux, type un Kontakt hébergeant seize instruments).

**Décision par défaut, assumée** : pistes Instrument, partout, jusqu'au template Full. Le Rack économise de la RAM sur les gros setups mais complique tout le reste (routing, export, lisibilité). Ton Sketch et ton Medium (l02) vivent très bien en pistes Instrument — et l'option **Import Track Archive / Track Presets** te permet de rapatrier une piste toute faite (instrument + réglages + couleur + Notepad-fiche) dans n'importe quel projet : c'est ta vraie unité de réutilisation, plus souple que le Rack.

### 2. MediaBay : les cinq minutes de réglage qui changent tout

Le MediaBay (F5) indexe tout ce que tu lui montres. Le réglage initial, une fois :

```
1. Panneau gauche : coche UNIQUEMENT tes dossiers de contenu réel
   (samples, presets) — pas le disque entier : l'index reste vif
2. Lance le scan complet une fois (la nuit s'il le faut)
3. Apprends DEUX gestes :
   - la recherche par attributs (Category: Strings, Character: Dark…)
   - la PRÉ-ÉCOUTE alignée : le preset s'écoute dans le tempo et la
     tonalité du projet — le pad s'auditionne DANS ta musique, pas à vide
```

### 3. La discipline du tagging : ta mémoire externe

Le MediaBay permet de noter (★) et de taguer tes presets. Le système minimal qui marche :

| Geste | Règle |
|---|---|
| ★★★★★ | réservé : ≤ 20 sons par catégorie (la présélection d'urgence — quand l'inspiration est là, on ne cherche que dans les 5 étoiles) |
| Tag par usage produit | tes moods : `epic`, `neo-noir`, `tension`, `romance`… — les vocabulaires du Module 9 deviennent tes clés de recherche : « pad + neo-noir » sort TES sons du genre |
| La règle du rejet | un son écouté et rejeté deux fois prend ★ (une étoile = « vu, non ») — on ne réécoute jamais deux fois le même déchet |

C'est le même principe que le Notepad-fiche de l02 : **infuser le savoir du produit dans l'outil**. Ta bibliothèque finit par être organisée par ta propre esthétique — c'est elle, la vraie « banque signature ».

### 4. L'hygiène des VST : trois règles de survie

- **Un projet qui doit durer n'utilise que des instruments que tu possèdes vraiment** (les démos qui expirent tuent les projets à la réouverture — six mois plus tard, le cue est muet) ;
- **note le patch dans le nom de piste ou le Notepad** (`STR Violins — [Banque] Sordino Legato`) : le jour où l'instrument ne charge pas, tu sais quoi rétablir ;
- la parade ultime vit en l10 (**Render in Place** : imprimer l'audio) — retiens dès maintenant que l'audio rendu est la seule immortalité d'un son.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Le Rack « parce que les pros » | routing spaghetti pour économiser une RAM que tu as | pistes Instrument jusqu'au Full |
| MediaBay qui indexe le disque entier | scan sans fin, index mou | les dossiers de contenu, rien d'autre |
| Auditionner à vide | le pad superbe seul, terne dans le projet | pré-écoute alignée tempo/tonalité, toujours |
| Zéro tagging | la demi-heure des quarante pads, à chaque fois | ★ discipline + tags-moods du Module 9 |
| Le son de démo dans un vrai projet | le cue muet à la réouverture | possédé ou rendu — pas d'entre-deux |

### La mission (m10-e06, déclarative)

Domestication initiale : index MediaBay propre, 5 Track Presets créés depuis ton template (les pistes avec Notepad-fiches deviennent réutilisables partout), et la première passe de tagging : 10 sons ★★★★★ répartis sur 3 tags-moods minimum. Checklist 8 étapes, `verifyHint` inclus (« nouvelle recherche 'pad + tension' : ton son sort-il ? »).

- [ ] Pistes Instrument par défaut ; Track Presets = mon unité de réutilisation
- [ ] MediaBay : index ciblé, pré-écoute alignée, deux gestes de recherche
- [ ] ★★★★★ ≤ 20 par catégorie ; tags = les moods du Module 9
- [ ] Possédé ou rendu : pas de son mortel dans un projet qui doit durer
