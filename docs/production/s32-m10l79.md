# SECTION 32 — MODULE 10, LEÇONS 7–9 (INTÉGRALES)

## 32.1 LEÇON m10-l07 — « Routing, groupes, bus : l'orchestre câblé »

```mdx
---
id: m10-l07-routing
module: module-10-cubase
title: "Routing, groupes, bus : l'orchestre câblé"
estMinutes: 25
skills: { daw_workflow: 0.8, orchestration: 0.2 }
---
```

### Pourquoi câbler avant de mixer

Le routing est la plomberie du son : où va chaque signal, avec qui il se regroupe, quels traitements il partage. Une session bien câblée se mixe en minutes (l08) ; une session plate — quarante pistes directement dans le master — se mixe en heures et s'exporte en cauchemar (l14 : les stems). Le principe directeur vient du Module 5 : **l'orchestre pense en familles, ta session aussi**.

### 1. Les trois tuyaux (le vocabulaire, une fois pour toutes)

| Objet | Ce que c'est | Métaphore |
|---|---|---|
| **Sortie directe** (routing) | où le signal VA : piste → groupe → master | le tuyau principal |
| **Groupe** (Group Channel) | un canal qui reçoit plusieurs pistes : la famille en un fader | le pupitre du chef |
| **Send** (départ auxiliaire) | une COPIE dosée du signal envoyée ailleurs (FX Channel) sans quitter son tuyau | le micro d'ambiance |

La confusion send/routing est LA source des sessions incompréhensibles : le routing déplace le signal, le send le *duplique en dosant*. La reverb commune de l02 était un send — tu comprends maintenant pourquoi : chaque piste garde son tuyau ET envoie un peu d'elle-même dans la salle partagée.

### 2. L'architecture standard (celle du template Medium)

```
Pistes                    Groupes            Master
STR Violins ─┐
STR Altos   ─┼──► GRP Strings ─┐
STR Celli   ─┘                 │
WW  Flûte   ─┐                 ├──► GRP Orchestra ──► Stereo Out
WW  Clar.   ─┼──► GRP Winds  ──┤
BR  Cors    ─┬──► GRP Brass  ──┘
BR  Tromp.  ─┘
SYN Pad     ─┬──► GRP Synths ─────────────────────► Stereo Out
SYN Sub     ─┘
                  FX Channels (alimentés par sends) :
                  FX Reverb Hall  ◄── sends de TOUTES les pistes
                  FX Reverb Room  ◄── (l08 : les deux profondeurs)
                  FX Delay        ◄── sends ponctuels (synthés surtout)
```

Trois décisions encodées dans ce schéma :

- **un groupe par famille** — le vocabulaire de m05-l01 devient des faders : « les cuivres trop forts » se règle en UN geste ;
- **un groupe Orchestra au-dessus des familles** — le tutti en un fader (et le sidechain futur du Module 6 remerciera) ; les synthés restent HORS de ce groupe : deux mondes, deux traitements (le brief hybride l'exige) ;
- **les FX en channels partagés, jamais en inserts par piste** — une salle pour tout le monde (la cohérence spatiale de l02) et une fraction du CPU.

### 3. Construire (la mission le fait faire — voici le pourquoi de chaque geste)

Créer un groupe : sélectionne les pistes de la famille → clic droit → *Add Group Channel to Selected Channels* — Cubase câble tout seul. Nommage : `GRP <Famille>`, couleur de la famille. Les FX Channels : *Add FX Channel* avec le plugin, puis le send se dose piste par piste (le petit slot Sends de l'Inspector). Ordre de construction : **groupes d'abord, FX ensuite, sends en dernier** — la plomberie avant les robinets.

### 4. Le piège des niveaux d'écriture

Dès que les groupes existent, une tentation : « égaliser » en poussant les faders de groupe. Retiens la hiérarchie (l08 la développe) : **la balance se joue d'abord dans l'ÉCRITURE** (la dynamique MIDI — ton CC1 de l04, les `dynamicPower` des fiches), ensuite dans les faders de pistes, en dernier dans les groupes. Un groupe Brass à −12 dB pour compenser des cuivres écrits fff est un mensonge : la maquette sonnera équilibrée, la partition ne l'est pas — et le jour d'un enregistrement réel, `orch.balance` avait raison depuis le début.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Tout dans le master, à plat | mix impossible, stems impossibles | les groupes-familles, dès le template |
| Une reverb en insert par piste | 12 salles différentes + CPU en feu | FX Channels partagés, sends dosés |
| Send confondu avec routing | des pistes « disparues », des doublages fantômes | le send duplique et dose ; le routing déplace |
| Synthés routés dans Orchestra | impossible de traiter les deux mondes séparément | deux arbres : Orchestra / Synths |
| Équilibrer aux faders de groupe | la partition ment | l'écriture d'abord, les faders ensuite |

### La mission (m10-e07, GUIDÉE)

Câble ton template Medium selon le schéma : 4 groupes-familles + GRP Orchestra + GRP Synths, 2 FX reverb + 1 delay en sends, nommage/couleurs. Checklist 10 étapes, `verifyHint` systématiques (« mute GRP Strings : TOUTES les cordes se taisent-elles ? » — le test de câblage en un clic).

- [ ] Routing déplace, send duplique-et-dose — plus jamais confondus
- [ ] Un groupe par famille, Orchestra au-dessus, Synths à part
- [ ] FX partagés en channels, jamais en inserts multipliés
- [ ] La balance vit dans l'écriture d'abord — les groupes ne mentent pas

## 32.2 LEÇON m10-l08 — « Le mix du compositeur : équilibrer sans mixer »

```mdx
---
id: m10-l08-mix
module: module-10-cubase
title: "Le mix du compositeur : équilibrer sans mixer"
estMinutes: 25
skills: { daw_workflow: 0.6, orchestration: 0.4 }
---
```

### Pourquoi « sans mixer »

Tu n'es pas ingénieur du son, et ce produit ne prétend pas t'en faire un. Mais ta maquette doit *sonner* — assez pour convaincre un réalisateur, assez pour que TES oreilles jugent ton orchestration. La bonne nouvelle : **le mix d'une maquette orchestrale bien écrite est à 80 % déjà fait** — par l'écriture (registres étagés, `orch.balance`, ton CC1). Cette leçon couvre les 20 % restants : gain staging, l'espace, et trois traitements — pas un de plus.

### 1. Le gain staging : de la marge partout

Le principe : chaque étage (piste → groupe → master) doit recevoir un signal confortable, jamais saturé. La discipline en trois chiffres :

```
Pistes :   les crêtes autour de −12 à −8 dB    (le fader de piste
                                                 proche de 0, c'est le
                                                 VSTi qu'on baisse si besoin)
Groupes :  jamais dans le rouge, faders ~0      (ils REÇOIVENT l'équilibre,
                                                 ils ne le créent pas — l07)
Master :   le tutti fff culmine vers −6 dB      (la marge de l02 §2.5 :
                                                 elle sert au limiteur du
                                                 jour de livraison, l14)
```

Pourquoi −6 et pas 0 : le headroom n'est pas de la prudence, c'est du **futur** — le mastering, les stems, la sommation. Un master qui tape 0 en cours d'écriture n'a plus nulle part où grandir.

### 2. L'espace : pan et profondeur (le seating plan)

L'orchestre a une géographie et ton auditeur la connaît inconsciemment. Le placement standard, à encoder dans le template une fois :

```
        fond :  percussions, cors (oui : les cors à gauche-fond ou
                centre-fond — leur pavillon vers l'arrière)
      milieu :  bois (flûte/hautbois centre-gauche, clar/basson centre-droit)
      devant :  V1 ──── gauche | Altos ─ centre | V2 ─ centre-droit?…
```
— convention moderne (seating américain) : **V1 gauche, V2 centre-gauche, altos centre-droit, celli droite, contrebasses fond-droite**. Cuivres au fond (cors gauche, trompettes/trombones droite), bois au centre-milieu, percussions fond.

Deux outils pour la *profondeur* (l'avant/arrière) — et te voilà au pourquoi des DEUX reverbs de l07 :

| Outil | Effet |
|---|---|
| **Le ratio send Room/Hall** | devant = plus de Room courte, moins de Hall ; fond = l'inverse. La distance s'entend dans la proportion de salle |
| **Le filtre coupe-haut léger** sur les pistes du fond | l'air mange les aigus : −2/3 dB au-dessus de 8 kHz et les cors *reculent* |

C'est tout. La profondeur d'une maquette tient dans ces deux gestes — le néo-noir (m09-l03) et sa « fondation sèche, reverb pour les voix » deviennent des réglages de sends.

### 3. Les trois traitements du compositeur (et l'interdiction du reste)

| Traitement | Usage légitime en maquette | La ligne rouge |
|---|---|---|
| **EQ soustractif** | creuser 2–3 dB là où deux éléments se masquent (le contrechant mangé par les cors : −2 dB aux cors vers 400–800 Hz — la version console de `orch.masking`) ; couper le grave inutile des pistes non-basses (coupe-bas ~80 Hz sur tout sauf celli/Cb/sub) | jamais d'EQ additif « pour embellir » : si ça manque de brillance, c'est l'orchestration (registre, doublure — M5/M7), pas l'EQ |
| **Compression douce** | UN compresseur léger (2:1, 2–3 dB de réduction) sur GRP Orchestra pour cimenter — éventuellement | pas de compression par piste en maquette orchestrale : ton CC1 EST la gestion de dynamique ; le compresseur qui le nivelle détruit ta leçon l04 |
| **Limiteur de contrôle** | sur le master, transparent, −1 dB de plafond : le garde-fou anti-clip | s'il travaille fort, le problème est en amont (gain staging) — le limiteur signale, il ne répare pas |

**La règle d'or de la leçon** : *quand la maquette sonne mal, la réponse est presque toujours dans l'écriture* — un registre encombré (`orch.density-overload`), une doublure manquante, un CC1 plat. Le fader est le dernier recours, pas le premier réflexe. Le produit et la console te disent la même chose ; celui qui l'apprend ici économise dix ans de forums de mixage.

### 4. La méthode d'équilibrage (20 minutes, dans l'ordre)

```
1. Tous faders à 0, tutti le plus dense en boucle
2. Gain staging : ramène chaque VSTi à des crêtes ~−10 dB piste
3. Le seating : pans + ratios Room/Hall + coupe-haut du fond (une fois
   par template, plus jamais ensuite)
4. Écoute EN MONO deux minutes (bouton mono du Control Room ou un
   plugin) : les masquages sautent aux oreilles sans le secours du pan —
   ce que tu entends mal en mono s'écrit mal
5. Corrige À L'ÉCRITURE ce que le mono a révélé ; EQ soustractif
   seulement si l'écriture a raison et le timbre a tort
6. Le limiteur de contrôle, et c'est fini : ta maquette est honnête
```

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Mixer AVANT d'orchestrer | des heures de faders pour cacher un registre encombré | l'écriture d'abord — le mono le révèle en deux minutes |
| Master qui tape 0 en écriture | plus de headroom pour livrer | le tutti à −6, la marge est du futur |
| Une seule reverb pour tout | tout au même plan, pas de profondeur | Room/Hall en ratio = la distance |
| Compresser chaque piste | le CC1 de l04 annulé, la vie aplatie | un seul, doux, sur Orchestra — ou rien |
| EQ additif partout | le son « amélioré » qui fatigue | soustractif, chirurgical, ou l'orchestration |

### La mission (m10-e08, GUIDÉE + auto-contrôle)

La passe d'équilibrage complète sur ta maquette de l04 (le cor vivant) enrichie de 3 pistes (cordes tenues, sub, percussion) : les 6 étapes de la méthode, checklist avec le **test mono** en `verifyHint` central (« en mono : le cor reste-t-il lisible sous les cordes ? sinon, quel registre encombre ? »). Déclarative — le produit ne peut pas entendre ton mix, mais il t'a appris à l'entendre toi-même : c'est le niveau 3 de §30.1 dans son plein usage.

- [ ] Crêtes −10 piste, tutti −6 master : la marge est du futur
- [ ] Seating + Room/Hall + coupe-haut du fond = la profondeur en trois gestes
- [ ] EQ soustractif, UN compresseur doux, un limiteur-garde-fou — rien d'autre
- [ ] Le test mono avant tout fader ; l'écriture avant tout traitement

## 32.3 LEÇON m10-l09 — « Logical Editor, PLE, macros : automatiser le geste »

```mdx
---
id: m10-l09-logical
module: module-10-cubase
title: "Logical Editor, PLE, macros : automatiser le geste"
estMinutes: 30
skills: { daw_workflow: 1.0 }
---
```

### Pourquoi apprendre à programmer sa DAW

Tout geste répété trois fois par session mérite d'être automatisé — c'est la définition du « pro workflow » que le brief exige. Cubase embarque pour ça un vrai petit langage : le **Logical Editor** (transformer les données MIDI par règles), son frère **Project Logical Editor** (transformer le projet : pistes, parts, visibilité), et les **macros** (enchaîner des commandes). Trente minutes ici = des dizaines d'heures rendues sur les années. Et tu vas te sentir en terrain connu : *le Logical Editor fonctionne exactement comme le moteur de règles du produit* — condition → action, un `Rule.evaluate` que tu écris toi-même.

### 1. Le Logical Editor : condition → action sur le MIDI

Ouvre-le (MIDI → Logical Editor). Deux panneaux :

```
FILTRE (la condition)                 ACTION (la transformation)
"Type = Note                          "Value 2 (velocity) : multiply by 0.9"
 AND Position = inside bar range…
 AND Value 1 (pitch) < C3"
```

Trois presets à construire maintenant — le kit de survie du module, chacun résout un problème déjà rencontré :

| Preset (nomme-le ainsi) | Filtre → Action | Le problème qu'il tue |
|---|---|---|
| `FIX — Kill GhostNotes` | Note AND velocity < 15 AND durée < 30 ticks → **Delete** | les miettes de jeu (frôlements de touches) qui polluent tes exports vers le produit — l'analyseur les voit comme des notes |
| `HUM — Velocity ±8` | Note → velocity **+ Random(−8..+8)** | la ligne martelée à velocity constante (l04 §4) humanisée en un clic — sur les ostinatos programmés, pas sur le jeu réel |
| `SEL — Strong Beats` | Note AND Position (bar range) = premier temps → **Select** | sélectionner tous les temps forts pour les accentuer (la hiérarchie de l08 M1, appliquée en masse : +10 velocity sur la sélection) |

La grammaire complète (Position, Length, Value 1/2, Channel ; les opérateurs ; les actions Transform/Delete/Select/Insert) se découvre en construisant — la mission fait construire. Ce qui compte : **penser en règles**. Tu écris depuis des mois des contraintes déclaratives dans tes exercices ; te voilà de l'autre côté du guichet.

### 2. Le PLE : les mêmes règles, à l'échelle du projet

Le Project Logical Editor filtre non plus des notes mais des **objets de projet** : pistes, parts, événements. Ses deux usages en or, couplés à la Track Visibility promise en l02 :

```
Preset "VIEW — Strings only" :
  Filtre : Track AND Name contains "STR"
  Action : Track Operation → Show ; (autre passe : NOT contains → Hide)
  → assigné à un raccourci : ta session de 60 pistes devient un poste
    de travail cordes EN UNE TOUCHE. Un preset par famille = le
    conducteur qui tourne ses pages tout seul.

Preset "COLOR — By prefix" :
  Filtre : Name contains "BR"  →  Action : Set Color (couleur cuivres)
  → le template importé en désordre se recolore en quatre frappes
```

C'est l'outillage réel de la Track Visibility « avancée » : les Agents de visibilité de l02 étaient statiques ; le PLE les rend programmables.

### 3. Les macros : la chaîne de gestes

Une macro = une liste de Key Commands exécutée d'un coup (File → Key Commands → Macros). La recette : **toute séquence que tes mains connaissent par cœur est une macro qui s'ignore**. Les deux à construire aujourd'hui :

| Macro | Enchaîne | Usage |
|---|---|---|
| `PREP — Export Mission` | Select All on Track → Logical Editor: Kill GhostNotes → Delete Overlaps → (Dissolve Part si multi-canal) | **la toilette d'export vers le produit** : chaque MIDI de mission prouvée passe par là — tes soumissions arrivent propres, l'analyseur ne juge que ta musique |
| `SAVE — Version+` | Save New Version → (optionnel : Back up Project hebdo) | le Ctrl+Alt+S de l01, enrichi |

Les macros s'assignent à des raccourcis ou — mieux — aux pads d'un contrôleur MIDI : le studio d'un professionnel se pilote comme un instrument.

### 4. La discipline : une bibliothèque de presets nommée

Les presets Logical/PLE/macros se nomment avec un **préfixe de famille** (`FIX —`, `HUM —`, `SEL —`, `VIEW —`, `PREP —`) : dans les menus de Cubase, ils se regroupent seuls et se lisent comme un vocabulaire. Même règle que les maps (l05) et le template (l02) : *la cohérence de nommage EST la vitesse*. Et même règle d'entrée : un preset se crée quand le geste a servi trois fois — pas de bibliothèque-wishlist.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Humaniser le jeu réel au Random | le rubato vivant remplacé par du bruit statistique | HUM sur le programmé ; le joué garde ses mains |
| Le Logical Editor découvert et oublié | les mêmes gestes manuels, à vie | les 3 presets du kit, construits AUJOURD'HUI, assignés |
| Des presets sans préfixe | la bibliothèque illisible dans 6 mois | familles nommées : FIX/HUM/SEL/VIEW/PREP |
| Exporter vers le produit sans toilette | ghost notes analysées, overlaps flagués | la macro PREP, systématique — c'est TA CI locale |
| Automatiser ce qu'on n'a jamais fait à la main | des règles fausses appliquées en masse | trois fois à la main d'abord — puis la règle |

### La mission (m10-e09, GUIDÉE puis PROUVÉE)

Construis les 3 presets Logical + 2 presets PLE + la macro PREP (checklist guidée, `verifyHint` par preset). Puis la preuve par l'usage : reprends l'export brut de ta mission l03 (garde toujours les bruts !), **salis-le volontairement** (joue trois notes fantômes pp très courtes), passe la macro PREP, exporte, soumets. Le moteur vérifie : zéro note < 30 ticks, zéro chevauchement, et le contenu musical inchangé par rapport à ta soumission l03 (comparaison de séquences — `samePitchSequenceAsGiven` recyclé). *L'automatisation prouvée par son résultat : la boucle de §30.1 au complet.*

- [ ] Logical Editor = condition → action : le moteur de règles, côté studio
- [ ] Le kit : Kill GhostNotes, Velocity ±8 (programmé seulement), Strong Beats
- [ ] PLE + Visibility = le conducteur qui tourne ses pages ; macros = les gestes en accords
- [ ] PREP avant chaque export vers le produit — ma CI locale
