## 18.0 Conventions du lot (évite 49 répétitions)

**Erratum de numérotation, résolu selon la gouvernance §7.9** : le footer de l14 (§5.1) référençait `e22/e23`, réattribués depuis par la numérotation continue. Correction : l14 pointe désormais vers **m01-e49-tension-arch** (nouveau) et partage **m01-e30-cadence-lab** avec l16. Total : **49 exercices**.

**Champs par défaut** (omis ci-dessous quand identiques) :
```json
{ "spec": { "version": 1 }, "meter": "4/4",
  "styleProfile": { "id": "classical-common", "ruleWeights": {} },
  "rubric": { "correctness": 40, "constraints": 30, "craft": 30 },
  "rubricQuiz": { "correctness": 100, "constraints": 0, "craft": 0 },
  "isGenerated": false }
```

**Décisions de spec introduites ici** (à répercuter dans `@ma/shared`) :
1. `given.notation` : les matériaux fournis s'écrivent en notation textuelle du produit (`"C4:q D4:e"`), compilée en `Note[]` par `content-sync` au seed — même parseur que `MusicExample` MDX ;
2. Les quiz portent `spec.quiz = { interaction, items[], generator? }`. `interaction` : `"mc"` (choix multiple), `"keyboard-pick"` (cliquer des touches), `"roll-pick"` (cliquer des notes dans le roll), `"order"` (ordonner). `generator` décrit l'espace paramétrique des drills (l'Exercise Generator §4.3 étend la banque) ; les `items` listés sont l'échantillon canonique livré ;
3. `EAR_QUIZ` = V1 (§6.6). Chaque EAR_QUIZ porte `"mvpFallback": "THEORY_QUIZ"` : en MVP, l'item est affiché avec son bouton ▶ (Tone.js joue `play`) au lieu d'être purement auditif — dégradation douce, pas de trou de contenu.
