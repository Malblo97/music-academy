# SECTION 30 — MODULE 10 : CUBASE PRO 13, LE REAL-WORLD WORKFLOW

## 30.1 Positionnement — et la décision de conception qui conditionne tout

Ce module matérialise la promesse fondatrice du brief : *« pas un simulateur de DAW — un compagnon du workflow réel »*. Conséquence structurante : **le produit ne voit pas l'intérieur de Cubase**. Il faut donc décider honnêtement ce que le kind `DAW_MISSION` peut vérifier :

```
DAW_MISSION : trois niveaux de vérification, assumés dans la spec

1. DÉCLARATIF   la checklist auto-déclarée (§2.2) : l'élève coche les étapes.
                Score = complétion déclarée. XP modéré (×0.6), pas de scoring
                de qualité — on ne note pas ce qu'on ne voit pas.
2. PROUVÉ       la mission exige un ré-import : l'élève exporte son MIDI
                depuis Cubase et le soumet (Flux C, §1.5 — le retour du
                boomerang). LÀ, le moteur analyse réellement : la mission
                DAW se termine en soumission normale, scorée.
3. GUIDÉ        certaines étapes portent un `verifyHint` : la mission dit
                à l'élève COMMENT s'auto-vérifier dans Cubase ("joue la
                piste en solo : entends-tu la sourdine changer à la mesure
                5 ?") — le produit enseigne l'auto-contrôle, compétence
                de studio à part entière.
```

Extension de spec actée : `DAW_MISSION` porte `spec.checklist[]` (étapes : `{id, text, verifyHint?}`) et optionnellement `proofSubmission` (contraintes appliquées au MIDI ré-importé). C'est le niveau 2 qui rend ce module unique : **la boucle apprendre-dans-le-produit → faire-dans-Cubase → prouver-dans-le-produit** est fermée.

Prérequis : Modules 1–2 ; les fiches M5 pour les leçons de template. Les leçons citent les acquis (CC1/11 de l10 M1, Tempo Track promise en l10/l24 M1, Root Key de l05 M1).

## 30.3 LEÇON m10-l01 — « Le projet bien né »

```mdx
---
id: m10-l01-projet
module: module-10-cubase
title: "Le projet bien né : l'hygiène qui sauve des œuvres"
estMinutes: 20
skills: { daw_workflow: 1.0 }
---
```

### Pourquoi commencer par l'intendance

Aucun sujet n'est moins glamour, aucun ne coûte plus cher quand il est négligé. La différence entre l'amateur et le professionnel ne s'entend pas d'abord dans la musique : elle se voit dans le projet — parce que le professionnel **retrouve** (la version d'il y a trois jours, le stem demandé six mois après, la session qui s'ouvre sur une autre machine). Ce module entier repose sur des projets sains ; cette leçon installe les cinq réflexes en vingt minutes, pour des années.

### 1. Un projet = un dossier (la règle absolue)

Cubase te demande un dossier de projet à la création : **chaque projet a le SIEN**, jamais de partage. Structure recommandée :

```
MonFilm_Cue03_Poursuite/
├── MonFilm_Cue03.cpr            ← le projet (et ses versions, voir §3)
├── Audio/                        ← géré par Cubase, n'y touche pas
├── Exports/                      ← TES mixdowns et stems (tu la crées)
├── MIDI/                         ← tes exports .mid (→ les soumissions
│                                    "prouvées" du produit passent par là)
└── Refs/                          ← briefs, vidéos, maquettes reçues
```

Pourquoi c'est vital : la fonction **Back up Project** (sauvegarde consolidée vers un nouveau dossier) et tout archivage reposent sur cette unité. Un projet qui pioche son audio dans trois dossiers est un projet qui ne survivra pas à un déménagement de disque.

### 2. Nommer : le futur toi est un inconnu pressé

- Projets : `Projet_Cue_Version` — pas de « final », jamais (il n'existe pas ; le versioning s'en charge) ;
- Pistes : **le rôle avant l'instrument** quand tu travailles nos exercices — `MEL Cor`, `CTR Celli`, `BASS Cb`, `TEX Pad` : la nomenclature des rôles du produit (§1.4) devient celle de ta session, et l'export vers une soumission ORCHESTRATE se mappe tout seul ;
- Couleurs de pistes : par famille, avec la palette du produit si tu veux la continuité (cordes/bois/cuivres/synthés — §3.6) — la couleur est une information, pas une décoration.

### 3. Le versioning : Ctrl+Alt+S est ton assurance-vie

**Save New Version** crée `Projet-01.cpr`, `-02`, `-03`… dans le même dossier, sans dupliquer l'audio. La discipline :

```
QUAND versionner ?  avant toute décision destructrice ou douteuse :
  - avant de supprimer des pistes "qu'on ne garde pas"
  - avant une réécriture de section
  - en fin de journée, toujours
  - avant d'ouvrir le projet à quelqu'un d'autre
COMBIEN ?           les versions ne coûtent que quelques Mo (le .cpr seul).
                    Dix versions d'un cue = normal. On nettoie à la livraison.
```

Et l'**Auto Save** (Préférences) : intervalle 5 min, 10 sauvegardes — règle-le maintenant, une fois.

### 4. Les réglages de naissance (la check-list de création)

À chaque nouveau projet, dans l'ordre :

| Réglage | Valeur | Pourquoi |
|---|---|---|
| Sample rate / bit depth | 48 kHz / 24 bits (l'image vit en 48k) | changer après coup = conversion de tout l'audio |
| Tempo initial | ton tempo de travail, même provisoire | la grille a un sens dès la première note |
| Root Key du projet | ta tonalité | l05 M1 l'a promis : le Key Editor peut colorer le hors-gamme — ton `melody.out-of-key` visuel |
| Frame rate (si image) | celui de la vidéo reçue, vérifié | un mauvais frame rate = tous les repères faux (l12) |
| Le dossier `Exports/` et `MIDI/` | créés vides | l'intendance se fait à la naissance, pas dans l'urgence |

### 5. Erreurs fréquentes

| Erreur | Coût réel | Correction |
|---|---|---|
| « Untitled-37 » sur le Bureau | le projet introuvable, l'audio orphelin | un projet = un dossier nommé, dès la seconde zéro |
| Écraser le même .cpr pendant des semaines | la version d'avant-hier n'existe plus | Ctrl+Alt+S, réflexe pavlovien |
| « final_v2_VRAIfinal.cpr » | personne ne sait ce qui est quoi | versions numérotées, la plus haute est la courante |
| Sample rate décidé plus tard | conversion, artefacts, temps perdu | à la naissance, avec le frame rate |
| Audio importé « où il était » | le projet casse au premier déplacement | import AVEC copie dans le dossier Audio (option à cocher) |

### La mission (m10-e01, DAW_MISSION déclarative)

Crée le projet `Academy_M10_Setup` selon cette leçon : dossier dédié, sous-dossiers, 48/24, Root Key, Auto Save réglé, 4 pistes MIDI nommées par rôle et colorées par famille, puis Ctrl+Alt+S deux fois. Checklist de 9 étapes, chacune avec son `verifyHint` (« ouvre le dossier : vois-tu -01 et -02 ? »).

- [ ] Un projet = un dossier ; Exports/ et MIDI/ créés à la naissance
- [ ] Nommage par rôle, couleur par famille — l'information avant la décoration
- [ ] Ctrl+Alt+S avant tout acte destructeur et chaque soir
- [ ] Les réglages de naissance : 48/24, tempo, Root Key, frame rate

## 30.4 LEÇON m10-l02 — « Le template : ton studio prêt avant l'inspiration »

```mdx
---
id: m10-l02-template
module: module-10-cubase
title: "Le template : ton studio prêt avant l'inspiration"
estMinutes: 30
skills: { daw_workflow: 0.7, orchestration: 0.3 }
---
```

### Pourquoi le template est une décision artistique

L'inspiration dure vingt minutes ; charger des banques en dure quinze. Le template — ce projet-modèle qui s'ouvre prêt à jouer — n'est pas une commodité technique : c'est **la condition matérielle de la spontanéité**. Et sa composition est un autoportrait : les instruments que tu y mets sont ceux avec lesquels tu penseras. Cette leçon construit ton premier template sérieux, dimensionné à ta machine et adossé aux fiches du Module 5.

### 1. La philosophie : trois tailles de template

| Taille | Contenu | Pour qui / quoi |
|---|---|---|
| **Sketch** (8–15 pistes) | piano, un patch par famille (strings/brass/winds ensemble), 2–3 synthés, une reverb | la composition pure — 90 % de ton travail dans ce produit commence ici |
| **Medium** (30–60 pistes) | sections séparées (V1, V2, Va, Vc, Cb…), cuivres par pupitre, bois solistes, percussions, synthés | la maquette sérieuse, l'orchestration réelle |
| **Full** (150+ pistes) | tout, articulations éclatées ou Expression Maps complètes | les pros à machines lourdes — PAS ton point de départ |

**La vérité d'atelier** : le template trop gros tue plus de musique que le template trop petit. Commence Sketch, promeus en Medium quand tes exercices ORCHESTRATE le réclament. Le Full attendra que ta machine et ton métier le justifient.

### 2. Construire le Sketch (pas à pas, c'est la mission)

```
1. Nouveau projet "TEMPLATE_Sketch" (règles de l01)
2. Pistes instrument, DANS L'ORDRE DE LA PARTITION (bois en haut,
   cordes en bas — l'ordre du métier, celui du Module 5) :
   WW  Bois (patch ensemble)        │ le rack se lit comme
   BR  Cors (patch section)         │ un conducteur :
   BR  Trompettes                   │ c'est voulu, et ça
   PERC Timbales/percus             │ t'entraîne
   KEYS Piano                       │
   STR Violons / Altos / Celli+Cb   │
   SYN Pad sombre / Pluck / Sub
3. Chaque piste : nom, couleur famille, Root Key suivie
4. Un bus de reverb en send (FX Channel, une belle salle, ~2,2 s) —
   TOUTES les pistes y envoient un peu : l'orchestre dans UNE pièce
   (le pourquoi complet en l07–l08)
5. Volumes de repos : le tutti à ~-6 dB au master (le gain staging
   naîtra en l08 ; pour l'instant : de la marge)
6. Track Visibility : configure 2 agents — "Compo" (tout visible)
   et "Cordes seules" (tu découvres l'outil ; l09 le rendra puissant)
7. File → Save as Template, catégorie personnelle
```

### 3. Le template au service des fiches M5

Ton Sketch encode déjà de l'orchestration : le patch « Cors section » doit jouer dans `C3–C5` (le registre-or de la fiche §5.2) — mets une **note de piste** (le champ Notepad) : `"sweet spot C3–C5 ; ff = unisson ; aigu bref"`. Fais-le pour chaque piste : **ton template devient ton aide-mémoire d'orchestrateur**, les fiches infusées dans l'outil. Quand tu joues une ligne de cor au clavier, la fiche est à un clic — et le produit, lui, vérifiera au ré-import (`orch.range-violation` sur le MIDI prouvé : la boucle complète).

### 4. La maintenance : le template vit

- **Une modification par mois maximum**, notée (un template qui change chaque semaine n'est plus un repère) ;
- ce qui entre au template doit avoir **servi trois fois** dans des projets réels — le template n'est pas une wishlist ;
- versionne le template lui-même (`TEMPLATE_Sketch-03`) : les règles de l01 s'appliquent à lui d'abord.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Le template-cathédrale au jour 1 | 4 min de chargement, inspiration morte | Sketch d'abord ; la taille se mérite |
| L'ordre des pistes au hasard | tu cherches, donc tu sors du flux | l'ordre du conducteur, toujours le même |
| Pas de reverb commune | chaque instrument dans sa boîte : le "MIDI de démo" | un send global dès le Sketch |
| Le template-wishlist | 40 synthés jamais ouverts | trois usages réels avant l'entrée |
| Aucune note de piste | les fiches M5 restent dans le produit | le Notepad = l'orchestration infusée |

### La mission (m10-e02, déclarative + amorce prouvée)

Construis le Sketch complet (checklist 12 étapes), puis **joue 8 mesures libres dessus** (n'importe quoi : le but est de vérifier que tout sonne) et exporte le MIDI de la piste piano vers une soumission libre du Melody Practice — ta première traversée complète produit→Cubase→produit.

- [ ] Sketch → Medium → Full : la taille se mérite
- [ ] L'ordre du conducteur, les couleurs, les Notepads-fiches
- [ ] Une reverb commune dès le premier jour
- [ ] Le template vit : lentement, sur preuves, versionné

## 30.5 LEÇON m10-l03 — « Key Editor I : éditer comme on écrit »

```mdx
---
id: m10-l03-key-editor-1
module: module-10-cubase
title: "Key Editor I : éditer comme on écrit"
estMinutes: 25
skills: { daw_workflow: 0.8, rhythm: 0.2 }
---
```

### Pourquoi le Key Editor est ta vraie feuille de papier

Tu passeras plus d'heures dans le Key Editor que partout ailleurs : c'est là que les notes jouées deviennent des notes *écrites*. Bonne nouvelle : tu le connais déjà à moitié — le piano roll du produit en est le cousin direct (mêmes ticks, même grille, §1.4 : 480 PPQ partout). Cette leçon transfère tes réflexes et ajoute ce que Cubase fait en plus. La leçon 4 s'occupera de l'expression (CC) ; ici, les **notes et le temps**.

### 1. La grille et le snap : ta relation au temps

Le trio à maîtriser : **Quantize Preset** (la résolution de la grille : 1/8, 1/16, 1/8T…), **Snap on/off** (J — la touche que ta main gauche doit connaître), **Snap Type** (Grid pour écrire, Relative pour décaler sans réaligner).

Le piège annoncé en l09 M1 §5 se résout ici : des triolets involontaires viennent d'une grille en 1/8T oubliée. **Réflexe** : la grille se lit dans la barre d'état avant d'écrire — comme on vérifie l'armure avant de lire.

### 2. Quantiser : réparer sans tuer

La quantisation dure (tout sur la grille) produit la raideur que l10 M1 appelait « MIDI de démo ». L'échelle des remèdes, du plus doux au plus fort :

| Outil | Effet | Quand |
|---|---|---|
| **Iterative Quantize** (~60 %) | rapproche de la grille SANS coller | le défaut : garde ton rubato en le disciplinant |
| Quantize dur (Q) | tout sur la grille | ostinatos, patterns mécaniques (le tic-tac de m09-l04 le VEUT) |
| Swing (%) sur le preset | décale les contretemps | jazz, shuffle — la fenêtre de l09 M1 en un curseur |
| Pas de quantize du tout | le jeu brut | rubato assumé, cadenzas — et le produit s'en fiche : l'analyseur quantise pour lire les hauteurs (l10 M1 §4) |

**La règle de style** : la quantisation est un curseur d'esthétique, pas une correction orthographique — le thriller quantise dur, la romance à peine (les genres du Module 9 ont chacun leur réglage, et c'est un choix à faire *par piste*, pas par projet).

### 3. Les gestes d'édition qui changent la vie

Le produit t'a donné dessiner/déplacer/redimensionner. Cubase ajoute les gestes de *masse* — ceux qui font la vitesse d'un professionnel :

```
Sélectionner...
  toutes les notes d'une hauteur   → clic sur la touche du clavier virtuel
                                     (toutes les rondes de pédale d'un coup)
  du même type                     → Edit > Select : Equal Pitch / same...
Déplacer...
  d'un cran de grille              → Ctrl+←/→
  d'un demi-ton / d'une octave     → ↑/↓ , Shift+↑/↓
                                     (la transposition de l03 M2 : UN geste)
Doubler la sélection à la suite    → Ctrl+D (l'ostinato en trois frappes)
Legato (coller les fins aux débuts)→ la commande Legato — le legato de
                                     l10 M1 §3, appliqué en un raccourci
Couper les chevauchements          → Delete Overlaps (le nettoyage d'après-jeu)
```

Apprends-les EN JOUANT la mission — pas en liste. Trois sessions et ils sont dans les mains.

### 4. Les cousins : Drum Editor et Score Editor (savoir qu'ils existent)

- **Drum Editor** : le Key Editor pour percussions — chaque ligne = un instrument (kick, caisse claire…), les notes deviennent des losanges sans durée. Tu y passeras au Module 6 (patterns) ; pour l'orchestre, la percussion s'écrit très bien au Key Editor ;
- **Score Editor** : tes notes en notation. Utile pour *relire* (une harmonie à 4 voix se vérifie mieux sur portée) et pour préparer l'export vers un copiste — pas pour composer au MVP de ton apprentissage. Le produit te fait la même promesse côté StaffLite (§6.6) : la portée est une vue, le roll est l'établi.

### 5. Erreurs fréquentes

| Erreur | Symptôme | Correction |
|---|---|---|
| Grille 1/8T oubliée | le « flou rythmique mystérieux » (l09 M1) | lire la barre d'état avant d'écrire |
| Tout quantiser dur par défaut | la raideur généralisée | Iterative 60 % par défaut ; le dur se choisit |
| Éditer note à note ce qui s'édite en masse | des heures perdues | sélections par hauteur/type, Ctrl+D, Legato |
| Chevauchements ignorés | legato sale, voix fantômes dans les banques | Delete Overlaps en fin de session |
| Composer dans le Score Editor | joli, lent, frustrant | le roll est l'établi, la portée est la relecture |

### La mission (m10-e03, PROUVÉE)

Dans ton template : programme l'ostinato de m01-s18 (fourni en PDF-mission avec sa notation) au Key Editor — quantize dur assumé — puis la mélodie de m02-s21 jouée au clavier et traitée en **Iterative 60 %**. Exporte le MIDI des deux pistes et soumets : le moteur vérifie les hauteurs, les durées, ET le profil de quantisation (l'ostinato doit être mécanique, la mélodie doit garder de la vie — `quantizeInfo`, §4.1, sert enfin en mission).

- [ ] Grille lue avant d'écrire ; J sous la main gauche
- [ ] Iterative 60 % par défaut — la quantisation est un choix de style
- [ ] Les gestes de masse : sélection par hauteur, Ctrl+D, Legato, ↑/↓
- [ ] Roll = établi ; portée = relecture ; Drum Editor = plus tard
